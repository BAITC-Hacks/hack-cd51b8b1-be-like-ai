# Задание второму участнику: frontend и проверка сценария

Этот файл можно целиком передать второму участнику. Срок команды — около пяти часов; отсчёт ниже относительный, от начала совместной разработки. Backend и модели ведёт лидер. Frontend можно начать сразу, пока поднимается GPU-сервер.

## Твой результат

Создай веб-интерфейс ассистента совещаний на React + TypeScript + Vite в директории `frontend/`. Главный путь: загрузить запись -> увидеть реальный этап обработки -> прочитать саммари и реплики -> проверить и исправить поручения -> скачать PDF/DOCX.

API и поля описаны в [API_CONTRACT.md](API_CONTRACT.md). Следуй им буквально. До готовности backend используй явный режим моков, с заметной надписью «Демонстрационные данные». Создай собственный обезличенный пример. При ошибке API показывай ошибку, не выдавай мок за результат обработки.

## Что сделать

1. **Загрузка.** Поля: название, файл MP3/WAV, дата и время совещания (можно оставить неизвестными), часовой пояс, подтверждение уведомления участников о записи. Покажи состояние отправки и ошибку. После ответа 202 открывай страницу совещания.
2. **Обработка.** Покажи текущий этап из API: подготовка, распознавание, разделение голосов, извлечение поручений. Если модели ещё не готовы, выведи понятное сообщение. Повторный клик не должен создавать случайные дубликаты.
3. **Результат.** Одна рабочая страница: саммари, список решений и рисков, транскрипт с цветами говорящих и таймкодами, аудиоплеер, таблица поручений. На небольшом экране блоки идут последовательно.
4. **Проверка.** В поручении редактируются формулировка, исполнитель, дата и статус. Для неясного срока показывается исходный текст и «Требует уточнения». Правки сохраняются через PATCH; ошибка сохранения видима.
5. **Проверяемость.** Кнопка «Источник» ведёт к подтверждающей реплике и соответствующему моменту аудио. Имя говорящего можно исправить. Исполнитель может быть человеком вне списка участников или подразделением.
6. **Экспорт.** Кнопки скачивания PDF/DOCX обращаются к backend. Сам экспорт реализует лидер. Во время обработки кнопки недоступны.
7. **Список.** Покажи ранее загруженные совещания и их статусы. Если времени мало, достаточно компактного списка рядом с кнопкой загрузки.

Стиль: спокойный деловой интерфейс, хорошая читаемость, русские подписи, понятные состояния. Казахские буквы должны отображаться корректно. Сконцентрируйся на рабочем сценарии и проверке поручений.

## Границы работы

Твои файлы: `frontend/**`, `docs/FRONTEND.md`, `docs/DEMO.md`. Backend, корневое развёртывание и зависимости Python меняет лидер. Не меняй контракт в одиночку: отправь лидеру конкретное предложение. Используй отдельную ветку `codex/frontend`, если работаешь в отдельном клоне.

Не реализуй сейчас собственный сервер моделей, интеграции Teams/Zoom/Meet, внешнюю рассылку или СЭД. Предусмотри конфигурацию `VITE_API_BASE_URL` и Vite proxy `/api`; по умолчанию запросы должны быть относительными к origin приложения. В сборке не должно быть localhost-адресов или секретных ключей.

## Проверка перед передачей

- `npm run build` проходит; есть lockfile и краткая инструкция запуска.
- Загруженный файл проходит через настоящий backend, сетевые ошибки видны.
- После перезагрузки страницы открывается сохранённое совещание.
- Неизвестный срок не заменяется сегодняшней датой.
- «Спикер 1» не выдаётся за установленную личность.
- Правка исполнителя/срока сохраняется и попадает в экспорт.
- «Источник» открывает правильную реплику и момент аудио.
- Пустой список поручений и провал обработки корректно отображаются.
- Моки явно обозначены и выключены при защите реального конвейера.
- Нет внешних CDN, аналитики и загрузки встреч в сторонние API.

## Дополнительный вклад в качество

Попроси знакомого носителя казахского языка помочь записать два коротких обезличенных совещания: одно на казахском, другое со смешанной речью. Нужны два разных голоса, хотя бы два поручения, исполнитель, срок и одно уточнение. Вместе составьте текст и ожидаемые поручения. Синтетические материалы допустимы по ТЗ, но одинаковый голос для всех ролей не проверяет акустическую диаризацию.

Если это невозможно, явно сообщи лидеру: поддержку казахского нельзя считать проверенной только на русских примерах.
