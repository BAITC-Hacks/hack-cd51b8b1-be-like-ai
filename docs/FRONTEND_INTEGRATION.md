Лидер сообщил успешный ответ health со всеми тремя моделями. Отдельный smoke check на A100 также пройден; качество на реальных записях ещё нужно проверить. Внешняя проверка без авторизации 23 сентября 2026 года получила HTTP 403, поэтому доступ второго участника необходимо проверить в его браузере.

## Доступ

У Secure Link есть собственная авторизация Brev. Разрешить второму участнику доступ к этой ссылке под его учётной записью. После входа Brev приложение отдельно запрашивает `HACKALEM_ACCESS_TOKEN` — код, который лидер задал перед запуском backend. Передать его участнику приватно. Токен Hugging Face для интерфейса не нужен; секреты не помещать в переменные `VITE_*`, Git или браузерный код.

Сначала участник открывает `/api/health`, затем `/login`. Ответ health не требует кода приложения, но защита Brev применяется ко всей ссылке.

## Второй участник: собрать интерфейс

Для демонстрации frontend и API размещаются на одном адресе. В PowerShell, из корня своего checkout с исправленным frontend:

```powershell
cd frontend
$env:VITE_API_BASE_URL = '/api'
$env:VITE_USE_MOCKS = 'false'
npm ci
npm run build
```

Если обе команды завершились успешно:

```powershell
Compress-Archive -Path dist/* -DestinationPath ../meetora-frontend.zip -Force
```

Передать лидеру `meetora-frontend.zip` из корня checkout. Внутри архива непосредственно `index.html` и `assets/`, без дополнительной папки `dist/`. Также запушить исправления в `codex/frontend` и передать SHA коммита и результаты тестов. Архив сборки позволяет запустить демонстрацию, пока лидер получает доступ к новым коммитам.

## Лидер: установить сборку

1. Загрузить `meetora-frontend.zip` через Jupyter в `/workspace/`, рядом с папкой `hackalem-ai`, как ранее загружался backend-архив.
2. В новом терминале Brev выполнить:

```bash
cd ~/workspace/hackalem-ai
.venv/bin/python -m zipfile -e ../meetora-frontend.zip frontend/dist
test -f frontend/dist/index.html && echo 'Frontend index.html found'
```

3. После завершения текущей обработки записей перейти в прежний терминал с работающим backend, нажать Ctrl+C и запустить снова:

```bash
bash scripts/run_backend.sh
```

В этом терминале должны оставаться ранее заданные `HACKALEM_ACCESS_TOKEN` и `HACKALEM_SECURE_COOKIE=1`. Перезапуск нужен, поскольку backend подключает `frontend/dist` при старте приложения.

4. Открыть адрес команды, пройти вход Brev и ввести код приложения. Если вместо интерфейса остаётся JSON о готовности backend, проверить наличие `frontend/dist/index.html` и перезапуск процесса.

## Второй участник: проверка через готовый адрес

1. Загрузить короткую обезличенную запись с двумя реальными голосами и явно произнесённым поручением; дождаться `ready`.
2. Проверить текст, говорящих, исполнителя, срок и переход к источнику в аудио.
3. Изменить только статус поручения: исходная формулировка срока и причины проверки должны сохраниться. Обновить страницу и проверить сохранение.
4. Переименовать спикера, исправить исполнителя или дату, скачать PDF и DOCX и сверить сохранённые данные.
5. Проверить повторный вход после истечения сессии и доступность уже полученного транскрипта при ошибке этапа извлечения.

Все запросы интерфейса используют относительные адреса `/api/...`; аудио и экспорт также идут через этот origin. Для демонстрации не требуется запускать Vite на сервере или открывать порт 5173.

## Если нужна разработка с локальным Vite

Нельзя рассчитывать, что `VITE_PROXY_TARGET=https://meetorabelikeai-xnsl493w7.gobrev.dev` автоматически получит браузерную сессию Brev: запросы прокси выполняются процессом Node. NVIDIA рекомендует `brev port-forward` для прямого API-доступа без браузерных перенаправлений. Для такого режима отдельно настроить туннель и локальную авторизацию; схема выше со сборкой на сервере уже сохраняет один HTTPS origin и существующие настройки cookie.
