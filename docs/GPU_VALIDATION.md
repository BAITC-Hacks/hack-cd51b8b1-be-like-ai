# Проверка моделей на Brev

23 сентября 2026 года пользователь выполнил `python scripts/check_models.py` на сервере A100-SXM4-40GB после обновления pyannote.audio до 4.0.3. Основание — предоставленный вывод серверного терминала; это не локальный прогон на ноутбуке разработчика.

## Подтверждено

- Все три набора локальных весов обнаружены: ASR, диаризация, извлечение.
- ASR и pyannote успешно инициализировались на синтетической тишине.
- Qwen загрузил 5 из 5 файлов весов; строка загрузчика показала около 5 секунд. Это время загрузки весов, а не время обработки совещания.
- Из синтетической текстовой реплики извлечено одно поручение; схема и ссылки на источники прошли проверки приложения.
- Пик выделенной PyTorch памяти — **15.64 GiB**. Эта метрика исключает CTranslate2 и не является полным использованием видеопамяти процесса или GPU.
- Итоговая строка: `MODEL CHECK OK`.

Предупреждения о TF32, устаревающем `torch_dtype` и параметрах случайной генерации не остановили проверку. В коде используется `do_sample=False`; данный прогон не требует включения TF32 или изменения параметров генерации.

## Что ещё нужно проверить

Тишина не проверяет качество распознавания и определения говорящих. Один синтетический текст не оценивает полноту поручений, исполнителей, дат и саммари на аудиозаписях.

Следующие этапы:

1. Запустить backend через `scripts/run_backend.sh` с отдельным кодом доступа.
2. Проверить `/api/health` и защищённую сессию.
3. Обработать обезличенную запись с двумя реальными голосами: загрузка → ASR → диаризация → извлечение → сохранение → экспорт.
4. Сверить каждое поручение с репликами и прослушиванием; измерить полное время обработки и память через `nvidia-smi`.
5. Выполнить RU, KK и mixed-сценарии из `docs/DEMO.md` ветки frontend. Казахский текст проверяет носитель.

Для отдельного прогона реального файла, уже находящегося на сервере:

```bash
source scripts/activate_env.sh
python scripts/check_models.py --audio /полный/путь/test.wav
```

Этот скрипт выводит количество голосов, сегментов и поручений, но не сохраняет полный протокол. Для проверки содержания и экспорта использовать API и интерфейс. До этих этапов качество на предоставленных записях и поддержка трёх языковых сценариев остаются непроверенными.
