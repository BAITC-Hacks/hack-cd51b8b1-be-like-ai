# Долгое извлечение поручений и имена спикеров

## Что изменилось

Раньше один вызов LLM одновременно составлял протокол и предлагал имена. Имена становились видны только после полной генерации. Запрос и ответ содержали длинные UUID, а в журнале не было счётчика генерации. После ошибки JSON автоматически запускалась ещё одна полная попытка без общего ограничения времени.

Теперь:

- Внутри запроса к модели используются короткие ссылки `S1`/`T1`. Перед сохранением они строго преобразуются в исходные UUID. Неизвестные ссылки отклоняются; API и ссылки на аудио сохраняют прежние идентификаторы.
- Перед поручениями выполняется отдельное сопоставление имён с голосами. Оно использует самопредставление либо передачу слова с последующим ответом, сохраняет ссылки на реплики и выставляет `identification=suggested`. Подтверждённое пользователем имя сохраняется.
- Предложения имён записываются в БД сразу после короткого прохода, пока поручения ещё обрабатываются. Это позволяет показать их через существующий опрос GET совещания.
- В журнале есть загрузка весов, начало каждого этапа, количество входных и выходных токенов и прошедшее время. Текст записи, имена и секреты в журнал не выводятся.
- У прохода имён бюджет 60 секунд генерации, у поручений — 900 секунд на черновик, независимую проверку полноты и исправления JSON суммарно. При исчерпании основного бюджета статус становится `failed`, код — `EXTRACTION_TIMEOUT`, транскрипт, имена и уже полученный черновик сохраняются.
- Второй проход проверяет каждую реплику, включая поручения вне нумерованного списка. Поле `extraction_checked_segments` показывает охват проверки, а не доказанную точность. Каждое поручение содержит дословную цитату; уникальная точная цитата позволяет исправить ошибочную ссылку на соседний сегмент.

Бюджет проверяется после каждого шага генерации Transformers. Он не прерывает зависший драйвер CUDA, загрузку весов или выполняющийся GPU kernel; это не жёсткий таймаут отдельного процесса. Если счётчик долго не меняется, нужны `nvidia-smi` и журнал процесса. При нехватке памяти GPU приложение сообщает `GPU_OUT_OF_MEMORY`.

## Установка обновления через Jupyter

Архив `meetora-extraction-fix.zip` содержит изменённые файлы backend, скрипты и документацию. Он не содержит модели, записи, базу данных, секреты или frontend.

1. Остановить backend через Ctrl+C в его терминале. Саму VM оставить включённой.
2. Загрузить архив **внутрь папки `hackalem-ai`** в файловой панели Jupyter.
3. В прежнем терминале выполнить:

```bash
cd ~/workspace/hackalem-ai
.venv/bin/python -m zipfile -e meetora-extraction-fix.zip .
source scripts/activate_env.sh
python scripts/retry_extraction.py --latest
```

Команда выбирает последнее ошибочное или прерванное совещание, в котором уже сохранены транскрипт и голоса. ASR и диаризация повторно не запускаются. Готовый протокол команда не изменяет. Для конкретной записи можно использовать `--meeting UUID` вместо `--latest`.

После строки `READY` запустить API:

```bash
bash scripts/run_backend.sh
```

Затем обновить страницу совещания. Код доступа и `HACKALEM_SECURE_COOKIE=1` должны оставаться в прежнем терминале, как при обычном запуске. Если повторная обработка завершилась ошибкой, API также можно запустить, чтобы увидеть сохранённый транскрипт и сообщение об ошибке.

Если архив загружен рядом с папкой проекта, путь при распаковке будет `../meetora-extraction-fix.zip`. Проверка расположения:

```bash
find ~/workspace /workspace -maxdepth 4 -name 'meetora-extraction-fix.zip' 2>/dev/null
```

## Диагностика

Во втором терминале выполнить:

```bash
nvidia-smi
```

В журнале основного процесса искать сообщения:

```text
LLM loading local weights onto cuda
LLM loaded in ...s
LLM speakers ...: input=... tokens max_output=1200 budget=...s
LLM extract ... attempt=1: input=... tokens max_output=9000 budget=...s
LLM extract ...: generated=... tokens elapsed=...s timeout=False
```

Рост счётчика подтверждает работу генерации. `timeout=True` означает остановку по бюджету. Предупреждение об одной попытке исправления JSON объясняет повторную генерацию. Наличие весов в health не измеряет эти этапы.

Если модель стабильно работает, но выбранная запись не укладывается в бюджет, до запуска можно увеличить его:

```bash
export HACKALEM_LLM_TIMEOUT_SECONDS=900
```

Сначала проверить реальные значения времени и количества токенов. Увеличение бюджета не исправляет ошибку GPU или некорректный JSON.

## Проверка имён

Для «Начнём с Батагус Нурлановны» + следующего содержательного ответа другого голоса разумно предложить имя отвечающему. Это контекстная гипотеза, которую пользователь может подтвердить или исправить. Обращение само по себе не устанавливает имя ведущего; поручение отсутствующему юристу не делает его участником записи. Проверять также неверное распознавание имени и ошибочное разделение голосов.

Автотесты проверяют ссылки, сохранение предложений до поручений, защиту подтверждённых имён, бюджет генерации, повторное использование транскрипта и отсутствие подстановки при ошибке. Они используют тестовый обработчик. Качество новых подсказок и скорость нового кода требуют отдельного прогона на A100 с реальной записью.

Механизм остановки: [Transformers 4.57.1 — stopping criteria](https://github.com/huggingface/transformers/blob/v4.57.1/src/transformers/generation/stopping_criteria.py). Режим без рассуждений сохраняет `enable_thinking=False`: [карточка Qwen3-8B](https://huggingface.co/Qwen/Qwen3-8B).
