# Проверка качества протокола

Наличие моделей, успешная генерация JSON и количество поручений не измеряют точность. Целевые 95% качества распознавания и 100% поручений нужно проверять на записях с независимо подготовленной разметкой.

## Изменения

- Первый проход извлекает поручения из всей беседы, сохраняя условия выполнения и дословную цитату-основание.
- Второй проход проверяет все реплики, добавляет пропуски и исправляет формулировки и сроки. Незавершённая проверка оставляет доступный черновик, но не выставляет статус готовности.
- Сроки ищутся также в соседних репликах. Календарный предлог восстанавливается по исходному тексту; год не придумывается. «На следующей неделе» и «до следующей недели» не считаются одинаковыми.
- Для совмещения слов с голосами используется exclusive diarization community-1. Нулевые интервалы слов относятся к единственному активному голосу с отметкой проверки.
- PDF показывает поручения в таблице с исполнителем, сроком, условиями и источниками. Предполагаемые имена остаются подсказками до подтверждения.

## Воспроизводимый запуск на A100

Проверка по умолчанию не изменяет исходное совещание. Не запускать вторую копию моделей одновременно с прогретым API на том же GPU. Сначала остановить API штатно, после проверки обязательно запустить его снова.

```bash
source scripts/activate_env.sh
python scripts/evaluate_quality.py \
  --meeting UUID \
  --data-dir "$PWD/data" \
  --model-dir "$PWD/models" \
  --output-dir "$PWD/data/quality-run"
```

Без `--retranscribe` проверяется только извлечение по сохранённому транскрипту. С `--retranscribe` повторяются ASR и диаризация. `--save-as-new` создаёт отдельную запись в приложении после успешной обработки; оригинал сохраняется.

Для заведомо русской записи можно перед запуском задать `HACKALEM_ASR_LANGUAGE=ru`. Для казахской/смешанной записи не оставлять этот параметр по ошибке. Число голосов и словарь задавать только по известным входным данным, а не подбирать по ожидаемым поручениям. Эталонный протокол не передаётся модели.

В каталоге проверки сохраняются исходный и новый JSON, черновик, PDF/DOCX, технические метрики и ответы модели. Они содержат текст совещания: не коммитить и не публиковать их в открытых логах.

## Ручная оценка

Для каждого эталонного поручения отдельно проверить: действие, объект, исполнитель, срок, условия и критерий выполнения, цитата и таймкод. Посчитать пропуски и лишние поручения отдельно; совпадение числа строк недостаточно. Имена/названия, неверно распознанные в исходном ASR, считать ошибками всего продукта даже при корректном извлечении по этому тексту.

Для распознавания речи нужна дословная эталонная расшифровка аудио. Перефразированный протокол не подходит для расчёта WER. Для голосов нужна разметка говорящих во времени. Проверять русский, казахский и смешанную речь отдельно.

Прохождение программных тестов доказывает работу проверок и сохранения данных; оно не гарантирует 100% правильность модели на новых записях.
