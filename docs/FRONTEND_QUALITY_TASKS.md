# Интерфейс проверки качества

Backend сохраняет прежние endpoints. Два новых поля необязательны для старых записей:
`Meeting.extraction_checked_segments` и `Task.evidence_quote`.

1. На этапе `extract` показывать уже пришедшие задачи как «Черновик, проверка продолжается». Если `extraction_checked_segments > 0`, показывать «Проверено реплик: X из segments.length». Это охват обработки, а не точность. Экспорт и подтверждение готовности доступны только при `ready`.
2. При `failed` не скрывать сохранённые транскрипт и черновик. Для `COVERAGE_CHECK_FAILED` объяснять, что проверка полноты не завершилась. Сетевую ошибку не подменять демонстрационными данными.
3. В раскрытии источника поручения показывать `evidence_quote`, исходные реплики и переход к аудио. Сохранять `description`: там находятся условия выполнения, охват площадок и требуемый отчёт.
4. Для `identification=suggested` показывать «Имя предложено ИИ». Дать подтвердить/исправить через существующий PATCH. Техническая метка «Спикер N» — не установленное имя.
5. Сравнить готовые протоколы с эталонами по каждому действию, исполнителю, сроку и условиям. Исправления человека сохранять минимальным PATCH только изменённых полей. Не показывать бейдж «100% точность» по числу задач или завершённому прогрессу.

Проверить сценарии: частичный результат → ready; частичный результат → failed; длинное описание; срок «на следующей неделе»; неизвестная дата записи; несколько источников; неподтверждённое имя; обновление страницы во время обработки.
