# HackAlem AI — ассистент совещаний

Из аудиозаписи система формирует проект протокола: транскрипт с говорящими, краткое содержание и поручения со ссылками на исходные реплики. Секретарь проверяет ответственных и сроки, сохраняет правки и выгружает PDF или DOCX.

**Статус:** backend реализован; 13 тестов API и правил обработки прошли с тестовым обработчиком. PyTorch проверен пользователем на Brev A100 40 GB, веса трёх моделей скачаны. Первый запуск остановился на загрузке pyannote; зависимость обновлена до 4.0.3 с официальным исправлением, повторный GPU-прогон ещё требуется. Интерфейс второго участника находится в `codex/frontend`; результаты его проверки — в [отчёте](docs/FRONTEND_REVIEW.md). Это основа для интеграции, не заявление о готовности всех требований ТЗ.

## Реализовано

- Загрузка MP3/WAV, подтверждение уведомления участников, необязательная дата совещания с часовым поясом.
- Один фоновый обработчик; этапы обработки, SQLite, сохранение промежуточного транскрипта и явных ошибок.
- Адаптеры локальных faster-whisper large-v3, pyannote community-1 и Qwen3-8B. Тяжёлые импорты происходят только при обработке.
- Таймкоды слов, сопоставление с голосовыми кластерами, признаки неоднозначного распознавания.
- Проверка структуры JSON и существования источников, консервативное вычисление сроков. Неизвестные даты сохраняются как `null`.
- Правка поручений и имён говорящих, история изменений в БД, статусы исполнения и вычисление просрочки.
- PDF с встроенным кириллическим шрифтом и DOCX; оба формата используют сохранённые правки.
- Код доступа, HttpOnly cookie, аудио Range, ограничение загрузки до 100 MiB и длительности до 60 минут.

**Ограничения:** нет бота Teams/Zoom/Meet, записи микрофона, планировщика напоминаний, внешних рассылок, СЭД, многопользовательских ролей и шифрования диска приложением. Контекст LLM ограничен 20 000 входных токенов; слишком большой транскрипт возвращает явную ошибку. Нет редактирования самого транскрипта через API. Казахский и смешанный сценарии ещё должны быть испытаны. WER, DER, точность поручений и скорость до измерений не заявляются.

## Разделение работы

**Лидер:** `backend/`, модели и GPU, `scripts/`, проверка аудио, интеграция и запуск. **Второй участник:** `frontend/` на React + TypeScript + Vite, загрузка, экран результата, аудиоплеер, источники, правки и скачивание.

Передать второму участнику [задание](docs/TEAMMATE_TASK.md) и [контракт API](docs/API_CONTRACT.md). Разбор требований и сложных случаев находится в [анализе ТЗ](docs/ANALYSIS.md). Тестовые данные интерфейса должны иметь явную маркировку; автоматического переключения на них при сбое API нет.

## Запуск на Brev A100

Выполнять в **терминале Ubuntu на сервере**, не в PowerShell ноутбука. Проект должен находиться в `~/workspace/hackalem-ai`. Архив переноса не содержит `.venv`, веса, исходные записи или секреты.

### 1. Окружение

Для новой VM из директории проекта:

```bash
bash scripts/setup_brev.sh
source scripts/activate_env.sh
python -m pip install -r requirements.txt
```

Если PyTorch 2.8.0+cu128 уже установлен и GPU test прошёл:

```bash
cd ~/workspace/hackalem-ai
source .venv/bin/activate
python -m pip install -r requirements.txt -r requirements-inference.txt
source scripts/activate_env.sh
python -m pip check
```

Нужны `ffmpeg`, `libsndfile1`, `fonts-dejavu-core`; их ставит setup-скрипт. `activate_env.sh` добавляет пути cuBLAS/cuDNN из venv. Драйвер NVIDIA переустанавливать не требуется. Основные версии закреплены в `requirements-inference.txt`; сохранить успешное окружение: `python -m pip freeze > runtime-lock.txt`.

### 2. Доступ и скачивание весов

Принять условия [pyannote community-1](https://huggingface.co/pyannote/speaker-diarization-community-1), создать [токен Read](https://huggingface.co/settings/tokens) и войти интерактивно:

```bash
hf auth login
```

На добавление в Git credentials ответить `n`. Токен не вставлять в репозиторий или переписку. Затем:

```bash
python scripts/download_models.py
```

Скрипт скачивает репозитории в `models/asr`, `models/diarization`, `models/llm` и сохраняет SHA каждой версии в `hackalem-model.json`. Для скачивания нужен интернет; записи не нужны. Повторить одну загрузку: `python scripts/download_models.py --only diarization` (также доступны `asr`, `llm`).

### 3. Проверка моделей

```bash
source scripts/activate_env.sh
python scripts/check_models.py
```

Ожидается `MODEL CHECK OK`. Проверка загружает ASR и диаризацию на тишине и извлекает поручение из синтетического текста; качество речи она не оценивает. Для реального испытания записать обезличенный пример с двумя голосами:

```bash
python scripts/check_models.py --audio /полный/путь/test.wav
```

Если старый архив устанавливал pyannote 4.0.1 и возникает `Weights only load failed`, выполнить [обновление до 4.0.3](docs/BREV_SETUP.md#ошибка-weights-only-load-failed--specifications). Повторно скачивать веса не нужно.

Модели запускаются из локальных каталогов при `HF_HUB_OFFLINE=1`, телеметрия pyannote и Hugging Face отключена. Флаги offline не являются сетевым экраном: закрытый режим отдельно проверить при заблокированном исходящем доступе.

### 4. Запуск API

Открыть отдельную сессию `tmux new -s hackalem`. В ней:

```bash
cd ~/workspace/hackalem-ai
read -rsp 'Придумай код доступа к приложению: ' HACKALEM_ACCESS_TOKEN
export HACKALEM_ACCESS_TOKEN
export HACKALEM_SECURE_COOKIE=1
bash scripts/run_backend.sh
```

Код доступа — отдельный секрет для входа в приложение, **не токен Hugging Face**. Скрипт запускает один процесс на порту `8000` и отказывается открывать сервер без кода. `Ctrl+B`, затем `D` отсоединяет tmux, сохраняя процесс; возврат: `tmux attach -t hackalem`.

В Brev → Access → Secure Links добавить HTTP destination port `8000`, сохранить ограничение доступа аккаунтом/командой. Открыть полученную **HTTPS**-ссылку, войти по коду. Порт Jupyter `8888` оставить для файлов и терминала. Доступны `/docs` и `/api/health`. Health проверяет наличие весов, не успешность вычислений.

Для локального HTTP во время разработки `HACKALEM_SECURE_COOKIE=0`; для HTTPS оставлять `1`. `.env.example` описывает параметры, но приложение **не загружает `.env` автоматически**: задавать переменные через shell или менеджер процесса.

### 5. Подключение интерфейса

Второй участник выполняет `npm run build` внутри `frontend/`. Сборка должна находиться в `frontend/dist`; перезапустить backend, и он начнёт обслуживать UI на `/`. Для маршрутов использовать `HashRouter`. При разработке Vite проксирует `/api` на `http://127.0.0.1:8000`.

Пока frontend отсутствует, корневая страница сообщает о готовности API и наличии `/docs`. Пример загрузки:

```bash
curl http://127.0.0.1:8000/api/meetings \
  -H "Authorization: Bearer $HACKALEM_ACCESS_TOKEN" \
  -F 'title=Проверка двух голосов' \
  -F 'timezone=Asia/Almaty' \
  -F 'participants_notified=true' \
  -F 'file=@/полный/путь/test.wav'
```

Если дата неизвестна, `started_at` не передавать. Полученный `meeting_id` использовать в GET `/api/meetings/{meeting_id}` до `ready` или `failed`.

## Проверки без GPU

Python 3.12, из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

На Windows активация: `.venv\Scripts\Activate.ps1`. GPU-зависимости для тестов API не нужны. `FakeEngine` существует только в тестах; production не подменяет ошибки демонстрационными ответами.

Проверены: цикл API с тестовым обработчиком, сохранение после перезапуска, правки, аудио Range, защита доступа, ограничения входа, ошибки моделей, ссылки на реплики, сроки и просрочка. PDF визуально проверен на синтетическом примере с русским и казахским текстом. DOCX проверен структурно; визуальный рендер на ноутбуке невозможен из-за отсутствия LibreOffice. До демонстрации открыть реальный DOCX в Word/LibreOffice и проверить страницы.

## Устройство и данные

```text
backend/app.py          HTTP API, доступ, загрузка и правки
backend/worker.py       один последовательный обработчик
backend/processing.py   декодирование, три модели, проверка результата
backend/deadlines.py    вычисление сроков и просрочки
backend/storage.py      SQLite и история правок
backend/exports.py      PDF/DOCX из сохранённого результата
scripts/               установка, скачивание, проверка и запуск
tests/                 проверки без GPU
docs/                  анализ, контракт и задание второму участнику
```

Медиа и БД находятся в `data/`, веса — в `models/`; каталоги исключены из Git. До удаления VM сохранить нужные данные. Политика хранения и удаления через UI пока не реализована.

Содержимое совещания — только данные. Модели не вызывают инструменты, не отправляют письма и не выполняют инструкции из записи. Ссылки на реплики повышают проверяемость, но не доказывают истинность выводов: секретарь должен сверить спорные поручения. Код доступа рассчитан на командный прототип, без изоляции отдельных организаций и пользователей.

Предоставленные записи не включены в репозиторий или архив. Brev — облачная VM с собственными моделями; допустимость загрузки чувствительных материалов определяется правилами организаторов. Для первого испытания использовать самостоятельно записанные обезличенные примеры. Внешние API распознавания и генерации не используются.

## Критерии демонстрации

1. Русская запись с двумя реальными голосами проходит весь конвейер; вручную сверены транскрипт, поручения, ответственные и сроки.
2. Казахская и смешанная речь проверены носителем языка; результаты и ошибки записаны без преувеличений.
3. Поручение открывает нужное место аудио; неизвестные даты не заменяются сегодняшней датой.
4. Правки сохраняются после обновления страницы и отражаются в PDF/DOCX.
5. Без доступа нельзя прочитать протокол или аудио. Проверен запуск с весами без исходящей сети.
6. Измерены время обработки и память; проверена инструкция запуска. UI, API и модели показаны как единая система.
